# 设定区 UI 重设计 — Requirements

**版本**: v1.0.0
**创建日期**: 2026-06-15
**状态**: draft
**依赖**: `jingwei-data-layer-unify`（统一 16 类 + 协同维护字段已落地）

---

## 问题陈述

经纬设定区当前以"图谱满屏"为默认视图，但图谱节点一多就变成视觉噪音；条目编辑是平铺单页，无法展示关系级联和协同审阅状态；伏笔缺乏专属看板，埋设状态只能靠 grep 追踪。

---

## 需求

### R1 分类浏览
- 系统**应**按统一 16 类分类浏览经纬条目。JingweiCategorySidebar 从 `unified-categories` 的 CATEGORY_META 读取分类列表，按 `book.visibleCategories` 过滤显示。

### R2 条目编辑多 tab 结构
- 条目编辑器**应**升级为 Codex 式多 tab 结构：详情 tab（基础字段）+ 关系 tab（级联引用）+ 追踪/AI注入 tab（可见性规则/注入策略/修订历史）。

### R3 关系 = 级联引用列表
- 关系 tab **应**展示当前条目的 relatedEntryIds 为"关联条目列表"（提到 A 自动带入 B 的上下文），点击可跳转。
- 图谱**应**降级为可选参考视图（非默认），用户主动点击时才渲染，标注"实验性"。

### R4 协同审阅展示
- 条目卡片**应**显示来源标记（user/agent/auto-settle）icon。
- 条目**应**显示修订历史摘要。
- conflictStatus=pending 时**应**红点标注 + 冲突详情可展开。

### R5 伏笔看板
- 伏笔类条目**应**用看板视图按状态机分列（已埋设→部分揭示→已回收→已废弃）。
- 卡片**应**显示：名称/埋设章节/目标章节/悬念天数。
- 悬念债务告警：埋设超过 N 章未回收的条目**应**有视觉警告。

### R6 正文联动接口预留
- 系统**应**暴露 `getEntryHighlightRanges(chapterId, entryId)` 数据接口。
- 本 spec 只建接口，正文高亮渲染为后续 spec。

---

## 非目标

- 正文内高亮渲染（后续 spec）
- 经纬图谱重新实现（本 spec 只做降级入口，不重做图谱）
- 移动端适配

---

## 验收标准

- AC1：侧边栏按 CATEGORY_META + visibleCategories 显示分类，点击切换条目列表。
- AC2：条目编辑器有 3 个 tab 可切换，数据正确加载。
- AC3：来源 icon 和冲突红点正确显示。
- AC4：伏笔看板按状态分列，悬念债务有视觉警告。
- AC5：图谱从默认视图移除，只在"实验性图谱"入口可进入。
- AC6：typecheck 干净 + Browser 截图验证。
