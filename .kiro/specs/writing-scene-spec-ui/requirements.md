# 写作区 scene.spec 可视化 — Requirements

**版本**: v1.0.0
**创建日期**: 2026-06-15
**状态**: draft
**依赖**: `jingwei-data-layer-unify`（统一分类落地后 scene.spec 的经纬引用正确）

---

## 问题陈述

scene.spec 是 pipeline.write 的核心输入（每章蓝图：场景列表/角色/冲突/伏笔进出），但当前只以 JSON 存在于系统内部，作者看不到也无法调整。写作结果不符预期时，只能重跑整个管线。

---

## 需求

### R1 章节蓝图面板
- 当写作区工作台显示 chapter/candidate 类型节点时，**应**显示"章节蓝图"面板（SceneSpecPanel），展示该章的 scene.spec 结构化数据。

### R2 数据展示
- 面板**应**展示：章节号/标题/字数目标。
- 每个场景卡片**应**展示：参与角色 / 地点 / 核心冲突 / 情绪曲线（起→终）/ 伏笔进出 / 写作约束。

### R3 作者可调整
- 作者**应**能在 UI 上修改 scene.spec 内容：调整场景顺序（拖拽）、修改冲突描述、增删角色、编辑约束。
- 调整后的 spec **应**可作为 pipeline.write 的输入。

### R4 生成入口
- 编辑器工具栏**应**有"生成蓝图"按钮，调用 scene.spec 工具生成/重新生成蓝图。

### R5 并排布局
- 蓝图面板**应**与正文并排显示（左正文/右蓝图），可收起。

---

## 非目标

- 蓝图版本对比（后续）
- 多章蓝图批量编辑
- 蓝图自动生成时机（当前只手动触发）

---

## 验收标准

- AC1：打开章节/候选稿时右侧显示蓝图面板。
- AC2：场景卡片正确展示角色/地点/冲突/情绪/伏笔。
- AC3：可拖拽调整场景顺序、编辑字段后数据持久。
- AC4："生成蓝图"按钮正确调用 API 并刷新面板。
- AC5：typecheck 干净 + Browser 截图验证。
