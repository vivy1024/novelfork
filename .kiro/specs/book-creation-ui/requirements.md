# 建书向导 UI 优化 — Requirements

**版本**: v1.0.0
**创建日期**: 2026-06-15
**状态**: draft
**依赖**: `jingwei-data-layer-unify`（已完成）

---

## 问题陈述

建书流程存在两个 UX 问题：

> **问题一：10 问向导不分书的轻重，所有题材走同一套问题。** 都市爽文作者被迫回答"力量体系""世界观"等无关问题（选"跳过"也增加认知负担）。

> **问题二：题材不在第一位。** 当前向导第 1 题是题材（正确），但后续 10 问全部固定展示，不因题材结果动态裁剪。数据层已有题材模板（轻/中/重），前端向导应据此动态跳问。

---

## 用户已明确的边界

- git 仓库建立保留不动（DashboardPage 创建表单的仓库选择不改）
- 建书两阶段结构可保持（创建表单 + 工作台内向导），题材在向导第 1 题已是正确位置
- 数据层已就绪（getGenreTemplate/createJingweiEntriesFromGuide/BookConfig.complexity）

---

## 需求

### R1 题材驱动动态跳问
- R1.1 向导第 1 题为题材（保持不变）。
- R1.2 用户选定题材后，系统**应**根据 `getGenreTemplate(genre).complexity` 动态决定后续展示哪些问题。
- R1.3 轻量题材**不应**展示：力量体系(powerSystem)、世界观(worldModel)。
- R1.4 中度题材**可**展示世界观（简化提示），**不应**展示力量体系。
- R1.5 重度题材展示全部问题。
- R1.6 跳过的问题**不应**计入进度条总数（"第 X / N 题"的 N 动态变化）。

### R2 向导完成后正确调用数据层
- R2.1 向导提交时**应**调用已有的 `/api/books/:id/guided-setup`（后端已改造为直建 SQLite）。
- R2.2 前端**不需要**改变提交 API——后端已处理题材模板选择。

### R3 向后兼容
- R3.1 已有书（已完成向导的）**不应**再次弹出向导。
- R3.2 全部跳过仍可用（"全部跳过，直接开始"按钮保留）。

---

## 验收标准

- AC1：选"都市"后向导只展示 8 题（跳 powerSystem + worldModel），进度条显示 X/8。
- AC2：选"修仙"后向导展示全部 10 题（含 powerSystem + worldModel）。
- AC3：选"系统流"后向导展示 9 题（含 worldModel，跳 powerSystem）。
- AC4：向导完成调 guided-setup API 正常，SQLite 经纬正确生成。
- AC5：全部跳过仍正常工作。
