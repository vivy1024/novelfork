# 设计分卷大纲

## 为什么

长篇中盘跑偏，根子大多在卷纲：上一级大纲给本卷分配的内容被漏掉、弱化或悬空，章节各自为战。卷纲的任务是把"全书承诺"拆成"本章任务"。

## 核心纪律：上级全量落地

- 分卷大纲必须承接总纲分配给本卷的**全部**内容：主线推进、支线、伏笔埋收、人物代价、信息释放。逐项核对，缺失一项就是结构缺陷。
- 无分部结构时，分卷直接承接总纲；有分部结构时，承接本部分配给本卷的内容。
- 每卷必须显式回答：本卷让主角离核心目标近了多少、付出了什么新代价、留下了什么新缺口。

## 卷纲要素（每卷必写）

1. **卷目标**：一句话说清本卷要达成的剧情结果（不是主题，是事件）。
2. **章号区间**：from/to，与总章数规划一致。
3. **章清单**：每章一行——本章任务、推进哪条线、埋/收哪个伏笔、章末钩子类型。
4. **节奏布点**：爽点/回报点分布（不能连续多章无回报），卷尾必须有阶段性高潮。
5. **卷末状态**：本卷结束时，哪些关系/实力/势力格局发生了变化（供下卷承接）。

## 章级蓝图（写章前展开）

- 每章按"约 3000 字"口径估算：一章只做一件事，多线章必须有一条主线。
- 章与章之间检查承接：上一章钩子在本章有回应；本章结尾给下一章留接口。
- 伏笔台账同步：每埋一个伏笔记入经纬 foreshadowing；每收一个更新状态。

## 终局储备（长篇防崩）

- 底牌（宿敌/真相/金手指上限）按卷解锁，不越级动用；升级台阶逐级给。
- 卷纲若出现"底牌提前动用""越级到顶"，如实报告并建议改纲，不得硬写。

## 操作（NovelFork）

1. `lore.read` 读总纲（category=outline）与伏笔（foreshadowing）。
2. 本 Agent 按上述结构生成卷纲与章清单。
3. `outline.volume` 写入并设为当前卷；`lore.write`（outline）补充细节时带 reason。
4. 写章时当前卷目标自动进入 preflight 与 scene.spec 上下文。
