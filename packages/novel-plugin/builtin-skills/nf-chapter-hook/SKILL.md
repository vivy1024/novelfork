# 强化章末钩子

## 为什么

网文读者点下一章只需要一个理由，但每章结尾都必须给。钩子弱，留存就塌；钩子同质，三章后也塌。

## 五类钩子（轮换使用，禁止连续同型）

1. **悬念型**：抛出一个未回答的问题（"箱子里是什么？"）。
2. **反转型**：刚刚确认的事实被推翻（"来的人不是他。"）。
3. **情感型**：情绪顶点悬停，下一章等一个回应（"他没有回头。"）。
4. **信息型**：泄露半条关键信息，另一半押后（"名单上有三个名字，第三个被涂掉了。"）。
5. **行动型**：主角踏出不可逆的一步（"他推开了那扇门。"）。

## 钩子落在具体事物上

- 一张没署名的收据、一通没接的电话、一个提前离场的人——比"危机即将到来"强一百倍。
- 钩子必须承接本章信息：用本章刚出现的人/物/事做钩，不凭空造。

## 钩子纪律

- 钩子承诺必须兑现：下一章要回应，兑现时带来回报（爽点/代价/新缺口）。
- 每埋一个钩子，用 hooks.manage 记入伏笔台账；回收时更新状态。
- 连续两章同型钩子视为失误；"欲知后事如何"式老评书钩子禁用。

## 操作（NovelFork）

1. 写章时在 scene.spec 蓝图的 hooks_planted 里声明本章埋的钩子。
2. 正文结尾按五类钩子之一写，写后用《去AI味重写》速查防套话。
3. `pipeline.write` 落盘后，`hooks.manage(action=plant)` 把钩子记入台账。
4. 兑现时 `hooks.manage(action=payoff)` 更新，让伏笔台账与正文一致。
