# 审阅章节正文

## 为什么

审阅不是挑错字，是回答一个问题：**这一章放进这本书，会不会让书变坏？** 裁判源是经纬与叙事记忆，不是审阅者的个人口味。

## 审阅前的裁判源装载（不可跳过）

1. 本章实际出场人物的人物传记（jingwei_read，category=characters）。
2. 与本章背景相关的故事设定/规则（world-model / rules / power-system）。
3. 近章记忆与时间线（memory_read，查角色状态、伏笔、事实链）。
4. 本章经 chapter_blueprint 校验的蓝图（若有）——核对承诺兑现。

## 五组检查

1. **人物**：言行是否符合传记（动机/边界/关系）；说话是否与他人的声口区分；有没有降智/工具人化；关键抉择是否承受了真实代价而非口头表态。
2. **设定与连续性**：与经纬是否冲突；时间线是否自洽（前章状态在本章正确延续）；有没有"知识越界"（角色知道他不该知道的）。
3. **POV 视角**：是否只从视角角色出发；有没有"他心想"类心理直写、角色看到自己看不见的部位/神情、无路标镜头跳切、上帝视角总结。
4. **场景与节奏（五步场景诊断 + 理想读者视角）**：
   - 核查章首抓力、中段回报、章末钩子是否成立，信息增量是否为零；
   - 对发闷或牵强的场景跑**五步场景分析**：① 驱动者与对抗力量的欲望是否直接相对（而非擦肩相切）；② 标注场景开端价值正负；③ 按潜文本行为模式拆节拍（同类重复只算一拍）；④ 对比结尾价值是否发生真实转折——起止价值无变化即为「非事件」；⑤ 定位期望与结果裂开鸿沟的转折点；
   - 模拟**理想读者**停顿点：标出哪里会让人分心放下稿子，并区分「作者明白但没写清（补清）」与「设定/因果本身没想透（重构）」。
5. **AI 味线索**：套话密度、句式均匀、对话同腔、冗余副词堆砌、模板化转折——按《去AI味重写》技能的四维病灶速查。

> 五步场景诊断详表见同目录 `references/scene-diagnosis.md`。

## 输出报告规范

- 每条问题必须可定位：章内段落/行号 + 原文摘录 + 冲突的裁判源出处。
- 分级：critical（设定/人物硬伤）/ warning（节奏/连贯风险）/ info（优化建议）。
- 每条给最小修改方向，不替作者做决定。
- 报告直接输出文本，不落盘；作者确认后才可改正文。

## 操作（NovelFork）

1. 按章节路径用原生 `Read` 读正文（未知路径先查 `chapter_list`）；`jingwei_read` + `memory_read` 装载裁判源。
2. 本 Agent 逐组检查，输出报告。
3. 作者确认后，局部用原生 `Edit`，整章重写用 `Write` 覆盖章节文件；再用 `chapter_commit`（mode=revision）校验并更新索引。
4. 改了剧情事实而仍需重结算时，用 `memory_settle` 传 chapterNumber。
