# 审阅章节正文

## 为什么

审阅不是挑错字，是回答一个问题：**这一章放进这本书，会不会让书变坏？** 裁判源是经纬与叙事记忆，不是审阅者的个人口味。

## 审阅前的裁判源装载（不可跳过）

1. 本章实际出场人物的人物传记（lore.read，category=characters）。
2. 与本章背景相关的故事设定/规则（world-model / rules / power-system）。
3. 近章记忆与时间线（memory.read，查角色状态、伏笔、事实链）。
4. 本章 scene.spec 蓝图（若有）——核对承诺兑现。

## 五组检查

1. **人物**：言行是否符合传记（动机/边界/关系）；说话是否与他人的声口区分；有没有降智/工具人化。
2. **设定与连续性**：与经纬是否冲突；时间线是否自洽（前章状态在本章正确延续）；有没有"知识越界"（角色知道他不该知道的）。
3. **POV 视角**：是否只从视角角色出发；有没有"他心想"类心理直写、镜头跳切、上帝视角总结。
4. **节奏与钩子**：章首抓力、中段回报、章末钩子是否成立；信息增量是否为零；有没有注水段。
5. **AI 味线索**：套话密度、句式均匀、对话同腔、模板化转折——按《去AI味重写》技能的四维病灶速查。

## 输出报告规范

- 每条问题必须可定位：章内段落/行号 + 原文摘录 + 冲突的裁判源出处。
- 分级：critical（设定/人物硬伤）/ warning（节奏/连贯风险）/ info（优化建议）。
- 每条给最小修改方向，不替作者做决定。
- 报告直接输出文本，不落盘；作者确认后才可改正文。

## 操作（NovelFork）

1. `chapter.read` 读正文；`lore.read` + `memory.read` 装载裁判源。
2. 本 Agent 逐组检查，输出报告。
3. 作者决定后：局部修正由本 Agent 生成新文本 → `rewrite.apply` 落盘；整章重写走 `chapter.write`。
4. 同步提醒：若审阅发现新事实，建议作者 `memory.settle_range` 结算。
