# 创建小说正文

## 提示哲学：给矛盾，不给题材

写作失败的第一原因不是模型不行，而是任务太宽。写章前先确认三个"矛盾"而不是三个"题材"：

1. **人物矛盾**：主角此刻要什么、怕失去什么、为此愿意付什么代价。三者缺一不可。
2. **场景矛盾**：这一章谁和谁在争什么，为什么现在必须争。
3. **信息矛盾**：读者已经知道什么、本章要新知道什么、还该被瞒着什么。

## 创作视角铁律

- 每章只从当前 POV 角色出发；不写他不可能知道的信息（知识越界），有限第三人称也**不能写角色此刻看不见的自己**（例如「她抬起无比羞怯的眼睛」——她自己看不见自己的眼睛）。
- 视角角色在场景里承受什么，就写什么；禁止上帝视角总结与旁白解读。确需切换视角时必须有明确叙事理由，并用换行/分节作为清晰路标，不在一两句内乱跳。
- 人物传记与故事设定是裁判源：出场角色的动机、边界、关系必须与经纬一致。

## 场景引擎：主动/被动交替与「鸿沟」

- **区分「行动」与「活动」**：人物按预期顺利做完的日常动作只是「活动」，不产生戏剧能量；真正的「行动」会在**主观期望与客观结果之间劈开「鸿沟」**，迫使人物投入更强意志、承担更大风险。
- **主动场景与被动场景**：
  - **主动场景（目标 → 冲突 → 挫折）**：以视点角色具体、可衡量的中间目标开场，中段用连续阻碍构成冲突，结尾让目标落空或付出更高代价（挫折）。
  - **被动场景（反应 → 困境 → 决定）**：承接上一幕挫折的情绪反应，权衡几个行不通的选项，最终把**决定落在不可兼得的价值取舍上**，直接引出下一场主动目标。过渡平淡时可压缩或跳过被动场景。
- **单一任务 + 最后时刻深切入**：每幕只承载一个核心故事进展；跳过到达、开门、寒暄等平淡过场，直接切入戏剧张力即将引爆的最后时刻。
- **粗略类比与描写留白**：环境与人物描写追求传神而非「使用说明」式参数罗列；用读者共享的日常尺度勾勒轮廓，在次要属性上留白，同一地点不重复详写。

> 场景节拍设计与描写留白速查见同目录 `references/scene-execution.md`。

## 开篇不铺垫

- 第一章三百字内出现读者能立刻理解的困境；前三章的任务是让人想看下一章，不是交代世界观。
- 设定用"正在发生"展示，不用"先解释"灌输；背景信息拆散在动作与对白里给。

## 核心驱动力设定（每章必答）

本章结束时，主角离他的目标**更近还是更远**？读者的情绪**涨了还是落了**？没有变化的章节是注水章。

### 主角防强行降智铁律

- 主角可以受挫、误判或吃亏，但**犯错只能源自三种合法原因**：信息差（当时确实无从得知）、对手藏得更深（反派同样在理性算计），或为了护住在乎之人被迫承担明知有风险的代价。
- **严禁**为了制造危机让主角无脑逞能、明知有陷阱却不留后手、或忽视前文自己亲手掌握的关键情报。

### 语言学去 AI 味 6 要点

1. **动词归位**：能用一个精准动词说清的动作，不拆成「弱动词 + 冗余副词/名词化短语」（如「进行了迅速的躲避」→「侧身让开」）。
2. **去「某某化/性」**：清掉「合理性/重要性/机械化/情绪化」等论文后缀，落回具体物件与行为。
3. **去生硬被动**：少用「被……所……」「受到了……的影响」这类翻译腔被动式，改回具体施动者主语。
4. **去解释性冒号**：非对话叙述中避免高频用「这不是偶然：……」「答案很明显：……」的结论冒号替读者总结。
5. **具象动作代抽象情绪**：写发紧的喉结、停在账目数字上的指尖，不直接命名「愤怒/震惊/恐惧」。
6. **保留留白**：把因果与重量交给动作、对白和物件自己说话，不在段尾或章尾加升华盖章句。

## 章结构（写前用 chapter_blueprint 确定）

1. **章首抓力**：承接上章钩子或抛出本冲突，前 300 字必须有事发生。
2. **中段回报**：至少一个读者能"爽到"的点（信息揭示/反杀/关系推进），不能只铺垫。
3. **章末钩子**：悬念型/反转型/情感型/信息型/行动型——留一个"必须点下一章"的理由。
4. **信息增量**：本章必须让读者知道至少一件前文不知道的事。

## 操作（NovelFork）

1. `chapter_preflight` 确认可写，取本章召回包（recall.text）和目标章节路径（targetChapterPath）；预检不过就停。用 Skill 读取相关写作技能。
2. `jingwei_read` 查出场角色/地点/规则；需要补看某一栏（如角色近况）再用 `memory_read`。禁止现编设定。
3. 用 `chapter_blueprint` 校验并缓存本章蓝图（含 beatBudget），拿到 `planMarkdown` 后立即通过 `EnterPlanMode` + `ExitPlanMode`（`mode="inline"`，直接传 `planMarkdown`）呈给作者审阅修改；审批通过后再开写。
4. **以召回包和已批蓝图为依据**，用原生 `Write` 流式写入预检的 `targetChapterPath`（写作台实时呈现草稿，勿自行拼路径或覆盖作者的改动）；写完后调 `chapter_commit` 完成审计、正式入库、自动 Git 记录并结算。召回过期就重新预检，其他阻断按提示用原生 `Edit` 修正后重调 `chapter_commit`，不把落盘草稿当成完稿。
5. 同轮收尾：结算失败用 `memory_settle` 传 chapterNumber；从正文提取的新设定用 `jingwei_write` 提交待审（layer=dynamic、status=needs-review）。

## 禁止

- 不写作者侧编号、工作语言（"本章/伏笔/细纲"）混进正文。
- 不把设定讲成教程；写成角色正在承受的事。
- 不因凑字数注水：每个场景必须有信息或情绪职责。
- 不强行降智主角制造危机：主角失手必须有信息差、对手设伏或被迫冒险的硬理由。
