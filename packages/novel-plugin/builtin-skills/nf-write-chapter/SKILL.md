# 创建小说正文

## 提示哲学：给矛盾，不给题材

写作失败的第一原因不是模型不行，而是任务太宽。写章前先确认三个"矛盾"而不是三个"题材"：

1. **人物矛盾**：主角此刻要什么、怕失去什么、为此愿意付什么代价。三者缺一不可。
2. **场景矛盾**：这一章谁和谁在争什么，为什么现在必须争。
3. **信息矛盾**：读者已经知道什么、本章要新知道什么、还该被瞒着什么。

## 创作视角铁律

- 每章只从当前 POV 角色出发；不写他不可能知道的信息（知识越界）。
- 视角角色在场景里承受什么，就写什么；禁止上帝视角总结与旁白解读。
- 人物传记与故事设定是裁判源：出场角色的动机、边界、关系必须与经纬一致。

## 开篇不铺垫

- 第一章三百字内出现读者能立刻理解的困境；前三章的任务是让人想看下一章，不是交代世界观。
- 设定用"正在发生"展示，不用"先解释"灌输；背景信息拆散在动作与对白里给。

## 核心驱动力设定（每章必答）

本章结束时，主角离他的目标**更近还是更远**？读者的情绪**涨了还是落了**？没有变化的章节是注水章。

## 章结构（写前在 scene.spec 蓝图里定）

1. **章首抓力**：承接上章钩子或抛出本冲突，前 300 字必须有事发生。
2. **中段回报**：至少一个读者能"爽到"的点（信息揭示/反杀/关系推进），不能只铺垫。
3. **章末钩子**：悬念型/反转型/情感型/信息型/行动型——留一个"必须点下一章"的理由。
4. **信息增量**：本章必须让读者知道至少一件前文不知道的事。

## 操作（NovelFork）

1. `write.preflight` 确认可写；用 Skill 读取相关写作技能。
2. `lore.read` 查出场角色/地点/规则；`memory.read` 查近章事实与状态——写前必查，禁止现编设定。
3. 提交 `scene.spec` 蓝图（含 beatBudget），校验通过后生成本章正文。
4. `pipeline.write` 提交正文：落盘、审计、章后结算由工具完成。
5. 写后同轮清零：结算失败（settlementError）时 `memory.settle_range` 补；新角色/新设定用 `lore.write` 落经纬待作者确认。

## 禁止

- 不写作者侧编号、工作语言（"本章/伏笔/细纲"）混进正文。
- 不把设定讲成教程；写成角色正在承受的事。
- 不因凑字数注水：每个场景必须有信息或情绪职责。
