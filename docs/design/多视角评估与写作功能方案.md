# 多视角评估与写作功能方案

依据：[路线与任务](../路线与任务.md) 当前状态、[参考项目学习](../90-参考资料/参考项目学习-2026-09.md)、2026-09-29 隔离实例浏览器验收截图，以及对应源码核对。本文是建议，不自动构成待办。

## 一、结论（先看这五条）

1. **功能够多了，缺的是把它们串成「写一章」的一条路。** 文风、声线、范文、伏笔、记忆、关系各有面板，作者得自己知道去哪、按什么顺序点。下一步以串联为主、少加新功能：做「章节循环」，把已有功能挂到循环的步骤上，旧入口随之下线。
2. **很多功能要作者先确认才生效，但确认入口散在五六处。** 声线、蒸馏规则、范文、伏笔草稿、关系事件都是「待确认才注入」。作者不去确认，这些功能对写作就等于没有，而作者自己并不知道。需要统一的「待确认」，并在每次写作时说清「有哪些因为没确认而没用上」。
3. **写作功能几乎都没用真模型验证过。** 蒸馏、声线、结算抽取、写作注入目前只有单测和模拟模型。先建一本「真模型基准书」，每个写作任务都在它上面跑出结果，作为完成条件。
4. **「人工比例」有两个量，要分开看。** 检测器给出的人工比例是结果；文风金库算的「作者改动比例」是作者投入的工作量。目标是前者变好、后者不必很高。不能把「作者改得多」当成功，也不做「分数不够就自动反复改写」。
5. **不影响写作质量的往后放。** 多 Agent 工作流、会话分享、PostgreSQL、设置页拆分都推后，集中力量把写作循环做完再出基线。

## 二、四个视角

### 2.1 网文作者（日更、长篇、要过平台检测）

作者要的：每天打开就知道今天写什么；写出来像自己；改得少；前后不崩（人设、伏笔、谁知道什么）；不被 AI 味卡住；书稿安全。

**做得好的**
- 文风一本书一份，规则带原文证据，确认后才生效。作者有掌控感，不会被静默改掉。
- 文风金库把「我改了哪里」变成可复用的范文，改稿有回报。
- 章节不管从哪改都能对账；自动保存不丢字；项目档案能备份、迁移。
- 伏笔到期 / 超期、记忆过期都有提示。
- 正文人名高亮加资料卡、人物关系网，查设定方便。

**不足（2026-09-29 验收时看到的实际界面）**
- **新书第一屏是报错。** 写作侧栏第一张是红卡「无用户本章指示，且作品基础中无可用当前焦点/大纲，无法确定写章方向」，下面四个 × / ! 检查项，写章按钮是灰的。新作者第一步就被挡住，也不知道该先做什么。
- **术语和内部名露在界面上。**
  - 经纬、叙事记忆、蓝图、结算、创作罗盘、章后事实、镜头这些词没有白话解释。
  - 资料卡里露出 `characters`、`dynamic`、「酒馆式一体化人物与设定全景总卡」「来源 manual」「置信 100%」。
  - 检查项里有英文 `Writing Skills`。
  - 章节标签页标题是文件名 `0001_雨夜.md`，面包屑是 `chapters › 卷01`。
  - 叙述者面板底部显示 `main +4327 -8878` 这种 Git 改动计数。
- **入口分散。** 确认声线在角色卡，确认规则在文风页，确认事件在章后事实，伏笔草稿在经纬；从「作品基础」打开设定图谱，活动栏会跳到「资源管理器」。
- **划词改写的结果回不到正文。** 续写、润色、改写、扩写、精简都交给叙述者，指令里写着「改完请把结果给我确认，不要直接覆盖正文」，结果只出现在对话里，作者得自己复制回去。只有本地规则的「人味化」能在选区里直接对比采用。
- **写完一章没有「自审 → 人味化」这一步**；写作时模型看了哪些资料，作者看不到。
- **「下一章写什么」没有一个地方直接回答**（作者已反馈 v0.0.3 的故事推进不好用）。
- **结算要人记得。** 结算只在叙述者调用工具或手动点「重新结算」时才跑，作者自己保存章节后不会自动结算。

### 2.2 叙述者使用者（在对话里驱动 Agent 的人）

**做得好的**
- 单一 Agent 契约：工具里不偷偷调模型做创作决定，创作由叙述者自己来。
- 面板和对话共用后端（蒸馏、声线、结算、采纳），两边结果一致。
- 工具拦截都带三段式解释（发生了什么 / 为什么 / 怎么办）；工作流里越出当前工序的写工具会被拦下。

**不足**
- **小说工具 51 个，还有兼容别名。** `lore.read` = `jingwei.read`，`lore.write` = `jingwei.write`；`memory.*` 就有 15 个。工具多了模型容易选错，也占上下文。
- **技能不可见。** 8 个作者入口技能新书不会自动启用；写作时注入了哪些技能、占多少字，看不到。
- **没配模型时体验断裂。** 叙述者面板显示「默认 ()」，Runtime 的 `/api/settings/context-thresholds` 直接返回 500。
- **叙述者不知道作者的确认积压。** 作者在面板上有 30 条待确认声线，叙述者写章时不会提醒。

### 2.3 首次使用的公开用户

- 七个平台的免安装 EXE，数据存本机，好。
- 要自己配模型，没配时提示不连贯（见上面的 500）。
- 没有起书引导（题材、主角、开篇、文风来源），得先懂「经纬」。
- 会话分享要作者主动发起、档案可导出，隐私方向对。

### 2.4 协作开发者

- 规则清楚：单一权威源、公开边界检查、隔离验证实例。
- 风险：主仓库大量改动未提交，fork 有只在本地的提交；换机器或合作者接手容易出事。
- 40 项任务里 13 项做了一部分，「完成」多数只有单测和模拟模型，缺真模型证据。

## 三、由此定下的做法（每个写作功能都遵守）

1. **挂到章节循环上。** 循环五步：① 准备下一章 → ② 写 → ③ 自审与人味化 → ④ 作者改 → ⑤ 收尾（结算与学习）。每个功能只在它那一步出现；新入口取代旧入口时，旧入口下线。
2. **确认要便宜。** 机器产物仍然先待确认（单一权威源规则不变），但集中到一处「待确认」：可批量处理，按对下一章的影响排序。写作时明确告诉作者「有 N 条声线 / 范文因未确认没用上」。
3. **结果回到原处。** 划词结果回选区对比采用；整章改动按段呈现改前改后，逐块采用，执行前核对章节版本。
4. **写作可见。** 每次写章给一张「本章用了什么」卡：焦点、伏笔、声线、范文、摘要、技能各几条、多少字，哪些被裁掉。受保护的不裁，放不下就报错。
5. **真模型验收。** 每个写作功能都在基准书上用真模型跑过，保存输入输出，作为完成条件。
6. **说作者的话。** 界面不露英文代号、文件名、内部分类名、Git 计数；「结算」这类词配一句白话说明。

## 五、每个写作功能怎么做

格式：作者要的 / 现在 / 怎么做 / 验收。「叙述者」指 Runtime 的 Agent；按单一 Agent 契约，创作判断和改写由叙述者做，工具只提供数据、机器检查和落盘。

### 5.1 起书接线（W2）

- **作者要的**：新书十分钟内写出第一章草稿。
- **现在**：已有「建书十一问」（`NewBookGuide`）：在作品总览画布上，书还没有章节时显示，答完推荐技能、生成经纬骨架（dynamic + needs-review），再交给叙述者收尾。但写作侧栏同时显示红色报错「无用户本章指示……无法确定写章方向」，两处没接上；已建过章节的书不再显示十一问。
- **怎么做**（不另做新引导）
  - 写作侧栏在书没有焦点与大纲时，不显示报错，改为一张卡：「先回答建书十一问」，点击打开作品总览里的十一问；已答过的显示「补全当前焦点」直接跳到创作罗盘。
  - 十一问答完直接进入循环第 ① 步，焦点已填好。
  - 十一问的文风一问可贴样文，贴了就建蒸馏任务后台跑，不挡写第一章（若十一问里没有这一问，只加这一问）。
- **验收**：新账号新书，不看文档，从写作侧栏走到能点「写第 1 章」。隔离实例浏览器实测。

### 5.2 准备下一章（T4.5 + T2.6）

- **作者要的**：打开就知道下一章写什么、必须处理什么。
- **现在**：创作罗盘（本章目标 / 必须守住 / 必须避开 / 备注）、伏笔到期提示、推进看板、记忆过期列表，分散在写作侧栏和故事推进里。
- **怎么做**：循环第 ① 步做一张「下一章」卡。
  - **焦点**：沿用创作罗盘四栏。叙述者给 1–3 个走向建议，每个写明依据（哪条剧情线、哪个伏笔到期）。建议属于创作决定，由叙述者生成；工具只提供依据数据。
  - **伏笔账本**：分本章到期 / 已超期 / 近期可用 / 待埋入四组。每条可选「本章处理 / 推到第 N 章 / 这次不管」，选择写进焦点。
  - **留白（T2.6）**：作者或叙述者写 1–3 条故意不写死的点（动机、细节、节奏），每条附真实答案。写作时告诉模型「这里至少两种写法，别写死」；答案只给模型参考，不写进正文。有效标准：至少两种合理写法、写出来明显不同。
  - **写前提醒**：记忆过期的章节有几章（建议先重新结算）；待确认积压里有哪些会影响本章。
  - **场景蓝图**：可选，保留「生成蓝图」，蓝图落盘为场景。
- **验收**：基准书第 11 章，卡片列出的到期伏笔与人工核对一致；作者的选择出现在「本章用了什么」卡里。

### 5.3 写章与上下文（T2.4 + T4.7 + T4.3）

- **作者要的**：写出来贴设定、像自己、不跑偏；知道模型看了什么。
- **现在**：已注入文风指南、按场景挑的 2–4 段范文、出场角色的已确认声线、近章摘要（过期的降权并标注）、伏笔等。检索日志有记录，但作者看不到；超预算时静默裁剪。
- **怎么做**
  - **受保护项**：作者焦点、硬状态、本章要处理的伏笔、留白答案、已确认声线。放不下时报错，并告诉作者可以删什么，不静默裁剪。
  - **可压缩项**：近章摘要、范文、关系背景，按优先级裁剪，并记下裁了什么。
  - **「本章用了什么」卡**：写完就显示，叙述者的结果卡里也有。内容是每类来源的条数和字数、被裁掉的、因为没确认而没用上的。数据取自已有的检索日志 `narrative_retrieval_log`。
  - **知情边界（T4.3 最小版）**：结算时让模型多抽一项「谁在本章得知了什么」，写入已建好的 `narrative_knowledge` 表。写作时给出场角色注入「他此时还不知道：……」。先只做人物知情，世界状态回放以后再做。
- **验收**：基准书里构造「秘密只有 A 知道」，B 出场的章节里 B 不会表现得知道；卡片内容与检索日志一致。

### 5.4 文风来源：预设与蒸馏（T2.1、T2.2）

- **现在**：网页与对话两个入口已通；规则带原文证据，逐条确认；断点可续跑。
- **不足**：真模型的抽取质量未知；一次可能出几十条，确认负担重；多来源对比没有界面。
- **怎么做**
  - 在基准书上用真模型跑，检查规则是否可执行：「对白后少用形容词收尾」可以，「文笔优美」不行。抽取时加校验：每条规则必须有一句「怎么做」和一段原文例子，否则丢弃或要求模型重写。
  - 审阅按维度分组（声音、节奏、对话、场景模板），低置信项默认折叠，提供「整组确认」。
  - 多来源对比做三栏：共同技法 / 来源差异 / 不应迁移。
  - 优先作者自己的旧稿；用他人作品时界面明确提示：只学写法，需有权使用。
- **验收**：作者从基准书的蒸馏结果里抽查 20 条可迁移规则，判定「能用」的不少于 70%。

### 5.5 角色声线（T2.3）

- **现在**：10 项声线，草稿 → 逐项确认，只注入已确认的；对白归属靠启发式。
- **怎么做**
  - 草稿的依据是角色卡加上已写章节里该角色的对白。对白归属改由结算时模型标注的说话人来定，不再靠启发式。
  - 写完一章后做「声线对照」：拿本章该角色的对白对照声线，标出「不像他会说的」句子，并入 5.6 的问题清单。
  - 按出场频率排优先级，只提醒作者确认出场多的角色。
- **验收**：基准书两个主要角色，隐去名字把对白给作者看，能分辨谁说的（作者主观判断）；人为插进去一句「不像他」的话，自审能标出来。

### 5.6 自审与人味化（T2.5）

- **作者要的**：写完就知道哪里 AI 味重，改起来快。
- **现在**：只有划词的「人味化」（本地规则）。已有去 AI 规则引擎、文风偏离检测 `detectStyleDrift`、AI 味评估（`engine/compliance/ai-taste-assessment.ts`）和朱雀检测客户端，都没串进写完一章之后的流程。
- **怎么做**：循环第 ③ 步。
  1. **诊断**：合并成一张按段落定位的问题清单，正文里同步标出。来源有四个：
     - 规则引擎的机器检查：高频 AI 词、句式模板、段落长度单调；
     - 叙述者按「自审」技能逐条引用原句并说明原因（语义判断）；
     - 声线对照；
     - 文风偏离。

     没问题就明说「这章读起来像人写的」。
  2. **人味化**：作者勾选要处理的问题（或全选），叙述者用七类手法只改这些段落：矛盾的情绪、身体小细节、无关的念头、不完美的对话、环境作用于身体、注意到无关的东西、故意打乱节奏。改动不超过 10%，情节和对白不动。结果逐段显示改前改后，作者逐段采用（与 5.7 共用一套对比界面）。
  3. **作者硬约束**：写在文风预设的「本书原则」里，诊断和改写都读它。
- **验收**：基准书 5 章，润色后规则问题数和偏离值下降、检测分不变差、改动不超过 10%，作者主观认可。

### 5.7 作者改稿：划词与整章改动（W4 + T5.3）

- **现在**：划词结果进对话，要手动复制回正文；整章 AI 改动没有逐块对比。
- **怎么做**
  - **划词**：叙述者改完后调用一个「提交选区修改」工具，结果带着原文指纹回到编辑器选区，显示改前改后，可以采用、拒绝或再改。原文已被改过就拒绝覆盖并提示。
  - **整章**：叙述者改整章时先给改动计划（逐段改前改后），写作台显示对比，逐块采用；执行前核对章节版本。
  - **回滚**：可以退回到某次 AI 改动之前，基于已有的章节历史。
- **验收**：浏览器实测划词五种动作的结果都能回到选区；同时有人在编辑时拒绝覆盖。

### 5.8 改稿学习：金库与写法记忆（T2.7 + T3.5）

- **现在**：金库能算作者改动比例，改稿段可存为范文。
- **怎么做**
  - 写作台编辑时显示本章「作者改动」小徽标，保存时更新。
  - 收尾第 ⑤ 步自动列出本章改得最多的 3 段，一键存为范文（仍需确认）。
  - **写法记忆**：作者对叙述者说「记住这种写法」，或在改稿段上点「记住」，叙述者生成一条写法预览（怎么做、例子、适用场景），确认后写进文风预设的本书层。普通聊天不写入。
  - 范文攒到一定数量（比如 20 段）时，提示重算统计指纹。
  - 界面写明：改动比例是作者投入量，不是检测分。
- **验收**：说「记住」之后，下一章的「本章用了什么」里能看到这条写法，基准书对比能看出用上了。

### 5.9 章后结算与记忆（T4.1、T4.2、T4.3、T4.4、T4.6）

- **现在**：结算时由模型抽取事件；实体索引、关系网、伏笔派生、记忆过期都已做。
- **不足**：没在真书上测过；关系的抽取规则 2026-09-29 才改；事件多数进待审，积压大；结算要人记得触发。
- **怎么做**
  - 收尾第 ⑤ 步：作者保存章节后自动排队结算，不用人记得。
  - 结算结果显示为一张「本章变化」卡：人物状态、关系、伏笔推进、新设定，每条可以确认、修改或驳回，同时进入统一待确认（W3）。
  - 知情边界并入这一步（见 5.3）。
  - 用真模型在基准书上结算 10 章，人工核对事件准确率、关系正确率、实体归并率，得出数字。
- **验收**：基准书上事件准确率不低于 80%、关系网与人工标注一致；作者确认一章的变化不超过 2 分钟。

### 5.10 审稿（审这一章：技能 `nf-review-chapter` + 工具 `chapter.audit`）

- **怎么做**
  - 审稿分两组维度：一致性（人设、设定、时间线、知情边界，机器检查加模型判断）；网文维度（章末钩子、节奏与爽点、黄金三章、追读力），可选。
  - 审稿结论可以勾选 → 生成修改 → 对比采用（同 5.7）。
- **验收**：在基准书里人为埋 5 处矛盾，至少找出 4 处。

### 5.11 检测与多模型（T2.8：作者不用朱雀，检测部分不做；多模型对比推后）

- **怎么做**
  - 每章可选朱雀检测，记录分数，按章画趋势，和作者改动比例放在一起看；不做「分数不够就自动重写」。
  - 多模型：同一章让 2–3 个模型各写一版，候选存副本不碰正文，交叉评审并给理由，作者选一版或合并。
- **验收**：基准书上用文风预设前后各写 3 章，检测结果和作者主观评价都有改善。

### 5.12 旧稿导入与拆书（T4.2）

- **怎么做**
  1. 导入后先保存原稿快照；
  2. 切章预览，作者可以调整切分；
  3. 后台逐章结算，进度可恢复；
  4. 全书汇总成经纬草稿（人物、设定、伏笔），全部待确认；
  5. 可选：从旧稿蒸馏作者本人的文风，这是最好的文风来源。
- **验收**：导入 50 章旧稿，切章正确，汇总出主要人物和主要伏笔。

### 5.13 导出与发布

- **现在**：`publish.export` 最小发布包（作品信息、目录、正文、投稿建议），`publish.check`，AI 使用声明生成。
- **怎么做**：按常见平台格式导出（分章 txt、docx）；发布前检查错别字、敏感词、字数和 AI 使用声明。如实声明 AI 使用。
- **验收**：导出文件格式符合平台后台要求（人工核对）。
