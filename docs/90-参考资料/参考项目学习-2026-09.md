# 参考项目学习（2026-09）

为 [路线与任务](../路线与任务.md) 提供依据：每个参考项目学什么、落到哪个任务、哪些不学。

**许可规则**：NovelFork 为 MIT。PlotPilot 带 Commons Clause，笔枢（Bishu Novel）、Scriverse、InkOS 为 AGPL-3.0，MuMuAINovel 为 GPL-3.0——这些只学机制与设计，**不照搬代码与提示词原文**。OpenWrite 为 Apache-2.0，其 `oh-story` 系列技能为 MIT，改编需保留署名与许可声明。

**来源等级**：「已核」= 本仓库维护者读过源码；「转述」= 来自 OpenWrite 的核查文档 `docs/TARGETED_NOVEL_PROJECT_REVIEW.md`，未经我们复核，落地前要自己核。

## OpenWrite（已核，`LiPu-jpg/Openwrite` main，2026-09-17，v0.2.10）

**形态变化**：已从独立应用改为 DeepSeek Harness（dsh）的插件——宿主提供 Agent 与界面，OpenWrite Core 只提供小说领域能力，明确「不另建 Agent 引擎、不再造 RAG / lorebook / 第二套正文存储」。与 NovelFork 和 NarraFork 的关系完全同构。→ T1.0

**文风三层合成**（`presets/openwrite/skills/style-system`）→ T2.1、T2.2
- 通用技法层（去模板化规则、AI 腔词库 `craft/ai_patterns.yaml`、`humanization.yaml`）；来源包层（从用户提供文本提取）；本书层（确认版设定与约束）。三层合成一份 `composed.md`，另有 `fingerprint.yaml`。
- 来源包按维度拆：`voice` / `language` / `rhythm` / `dialogue` / `scene_templates` / `consistency`，外加 `setting_profile`；提取进度与分块结果单独存，可恢复。
- 每条发现分 `reusable`（写法、节奏、叙述距离、对话密度、结构习惯）与 `source_bound`（专名、口癖、专属组织、签名梗、作品特定规则），合成层只吸收 `reusable`。
- 流程：extract → review → promote（作者确认）→ synthesize；不内置任何参考作品风格库。

**预设与技能**（`presets/openwrite`）→ T3.1、T3.4、T3.5
- 一个长期会话预设 = persona + 约 24 个技能；斜杠菜单只保留 8 个作者入口：看进度、写下一章、审这一章、改这段、伏笔、设定、写法记忆、导出。其余技能 `user-invocable: false`。
- `/learn` 写法记忆：风格、成功钩子、作者偏好是作品资产，经预览确认写入；普通讨论不得写入；不建第二套记忆。
- `npm run test:preset` 断言作者入口存在、拒绝旧命令名。

**作者体验** → T2.8、T4.1、T4.5
- 模型测试：同一章节 / 大纲范围多模型独立生成、交叉评审，比较质量、可靠性与费用；候选存在隔离副本，不覆盖正文。
- 选区批注（不写入正文）、选区润色（扩写 / 缩写 / 去 AI 味 / 按审稿改这段，走修订与逐块应用，源版本不一致时拒绝覆盖）。
- 正文提及高亮：用人物 / 地点名与别名做最长匹配，点击打开只读资料卡。
- 伏笔行动清单：本章必须回收 / 已超期 / 待埋入，直接映射到可打开的行动。
- 每 50 章滚动规划窗口；网文可选审稿维（钩子、黄金三章、追读力）。

## PlotPilot / 墨枢（已核，本地 `plotpilot-ref`，2026-08-24）

- **文风金库**（`voice_vault_repository`、`voice_sample_service`）：按章与场景类型保存「AI 原文 + 作者改稿 + 差异分析」样本对，样本数达阈值后重算指纹；另有漂移检测。指纹本身只是形容词密度、平均句长，比我们现有的弱；可学的是**样本对**这个数据结构。→ T2.7
- **角色声线锚点**：角色投影里的 `voice_fingerprint`（风格、句式、语速、口头禅）作为高优先级系统提示。→ T2.3
- **关系模型**（`domain/cast`、`relationship_engine`）：角色 ID 之间的有向边，边上挂剧情事件；可查第 N 章的当前关系、关系史、路径、共同关系、关系强度与趋势（稳定 / 升温 / 恶化 / 起伏），并给出发展建议。→ T4.4
- 既有结论（8 月）：张力评分独立小调用、失败返回 -1 不造假分；伏笔五态机与收敛沙漏；上下文 T0–T3 预算与治理评分。

## 笔枢 Bishu Novel / DeterminFlow（已核，`plugins/bishu-novel`，AGPL-3.0）

- **组织方式**：7 条工作流（世界观六维、角色、故事规划与风格档案、卷纲与近纲、正文、润色、章后结算），33 个 Agent 提示词，**只有 1 个技能**（写作助手：维护书籍上下文、选下一条工作流、解释参数、监督落盘）。无数据库，目录即身份，文件检查点。→ T3.1、T5.2
- **人味链**（`polish` 工作流）：AI 味自审（只诊断，逐条引用原句，没问题就明确说「像人写的」）→ 人文化润色（改动不超过 10%，保留全部情节与对白，按七类操作「用真实置换虚假」：矛盾的情绪、小的身体细节、与主线无关的随机念头、不完美的对话、环境作用于身体、注意到无关事物、刻意的节奏断裂）→ 专业润色。用户可在提示词末尾加自定义硬约束（示例里有 15 条，如禁止直接命名情绪、限制高频 AI 标记词密度、段落长度须有起伏）。→ T2.5
- **风格档案**（style-profiler）：只定战略层——基调、参照作品（学什么 / 怎么用）、叙事人格、创作禁令、题材笔法；明令禁止写句长、比例、精确数字这类战术指令（那是写手与文风指南的事）。→ T2.1
- **角色声线**（character-voice）：从角色档案**提取**而非创造——声音定位、句式指纹（长短句、口头禅、停顿、常用句式）、认知滤镜、绝不会说的句式、愤怒 / 紧张 / 撒谎时的语言变化；信息不足标「待补充」。→ T2.3
- **信息黑洞**（novel-director）：章节规划里刻意留动机缺口、细节缺口、节奏缺口，每 2000 字不超过 3 条，每条附导演真实答案；有效性标准是「写手至少有两种合理处理，且结果明显不同」。→ T2.6
- **多写手**：正文可单写手一稿成型，也可按骨架分槽由对话 / 动作 / 内心 / 描写 / 过渡写手分别填写，再由整合写手合并。每节点独立会话、JSON 产物校验。→ T5.2

## OpenWrite 核查的七个项目（转述）

| 项目 | 学什么 | 任务 |
|---|---|---|
| ainovel-cli（Apache-2.0） | 正文接纳：用已接纳正文的 SHA 扫描磁盘改动，重新分析后再次核对 SHA，接纳、重建事实投影、使摘要与审阅失效；旧稿导入走源快照 → 语义切分 → 确认 → 逐章事实 → 全书综合 → 发布，步骤绑定输入指纹，未发布不许消费 | T4.2、T2.2 |
| Scriverse（AGPL） | 保存状态机：固定本次快照、等待在途请求、核对身份后只把该快照记为已保存；AI 写入先成为带 before/after 的计划，执行前重查版本与权限；稳定行 ID 让批注在改稿后能重定位 | T5.3、T6.2 |
| OpenFic（Apache-2.0） | 每轮 AI 改动面板（行级 / 并排 diff，可回滚到用户消息前）；检索索引状态分 fresh / stale / needs_rebuild / no_index 并告诉作者怎么修 | T5.3 |
| CharacterArc（MIT） | 待写入变更队列（接受 / 拒绝 / 提交，只写已接受项，区分部分失败）；`.carc` 项目档案打包正文、版本、关系、大纲、工作流文档、AI 记录与参考文本，导入可选模块、补依赖、重映射 ID | T5.3、T6.1 |
| MuMuAINovel（GPL） | 伏笔上下文四分：本章到期、超期、近期参考、待埋入；从评审结果勾选修改建议再生成并对比应用 | T4.5 |
| InkOS（AGPL） | 上下文分受保护与可压缩：作者意图、当前焦点、硬状态、活跃伏笔超预算时明确报错而不裁剪；trace 记录来源、理由、预算与压缩 | T4.7 |
| Casting-Workflow（MIT 声明） | 多来源并列比较界面：共同技法 / 来源差异 / 不应迁移的设定 | T2.2 |

## 8 月已核的其他项目（结论摘要）

- **Chevoink**：附件输入与番茄发布包。**OpenFic**：异步导出与 latest / near / mid / far 上下文。
- **TencentDB Agent Memory**：L0–L3 分层、批量去重、来源溯源、RRF 召回。**OpenViking**：compiled truth 与 timeline 分离、有向有权链接与反向链接。
- **Storyloom**：时间线交互、缩放、定位到事件、角色甘特。**Foliantica**：以某条目为中心的关系图、BFS 深度、节点定位、可配置时间单位。→ T4.4
- **Plottr**：章 × 线索的情节板网格（已用于推进看板）。

## NarraFork 官方插件 narrator-team（已核，`NarraFork/narrator-team` v0.1.49，MIT）

Leader 叙述者与 Worker 叙述者组成团队：`team.dispatch` 派发任务并写入共享队列，`team.status` 查看成员忙闲与最近回复，`team.context_broadcast` 把探索结论交接给执行者，`team.recruit` / `team.fire` 招募和解雇临时子代理，派发前对 Worker 计划做自动审查；提供团队面板视图。要求宿主 0.7.7+，标注为测试性、未来可能并入 NarraFork 本体。→ T5.1、T5.2

## NarraFork 0.7 插件能力（已核，`examples/plugins`）
