# 维护规则

## 1. 新功能准入规则

任何新功能在进入实现前，必须先回答四个问题：

1. 它属于工具层、配置层、事实层，还是结果层？
2. 它会不会制造新的中间对象？
3. 它会不会和现有概念重叠？
4. 它是否真的需要成为独立对象？

如果答案不清楚，先写入 CodeWiki，再决定实现。

## 2. 删除规则

删除任何旧概念前，必须同步更新：

- 删除清单
- 决策日志
- 受影响的测试或边界说明

不能只删代码，不留记录。

## 3. 文档规则

- 文档必须反查到代码
- 代码必须能定位到对应文档
- 文档中的废弃项必须保持可追踪
- 重要概念变更必须在决策日志中记录理由

## 4. 漂移检查规则

每次大改后都要检查：

- 文档引用的文件是否还存在
- 文档中的接口名是否还有效
- 旧概念是否又重新进入主路径

## 5. 维护心法

- 先收口，再扩展
- 先删中间层，再谈优化
- 先统一真相源，再谈兼容
- 先让文档记住系统，再让系统记住文档
