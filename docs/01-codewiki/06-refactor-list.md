# 整理清单

## 1. 需要保留并明确边界的对象

### 1.1 正式章节

正式章节保留为独立业务对象，但只作为写作动作的稳定结果，不再和候选稿/草稿体系绑在一起。

需要明确：
- 正式章节的生成入口
- 正式章节的编辑入口
- 正式章节和叙事记忆的回写关系
- 正式章节和导出/展示的关系

### 1.2 叙事记忆

叙事记忆是动态事实的唯一主归属。

需要明确：
- 哪些变更必须回写叙事记忆
- 哪些信息只属于记忆，不应落到正文对象
- 哪些分析结果只是建议，不是事实

### 1.3 经纬

经纬是静态参考的唯一主归属。

需要明确：
- 哪些内容属于静态设定
- 哪些内容不应被动态流程覆盖
- 哪些工具可以读取经纬但不能改写其结构

### 1.4 创作配置层

包括：
- 写作预设
- 模板
- 节拍
- 风格配置

需要明确：
- 用户可编辑性
- 文风提取建议如何转为配置
- 配置的版本管理方式

## 2. 需要整理为工具的能力

### 2.1 文风提取

整理为工具，不是对象。

需要明确：
- 提取结果的结构
- Agent 是否询问用户是否加入预设
- 用户是否可手动编辑预设 / 模板 / 节拍

### 2.2 选段扩写

整理为编辑工具。

需要明确：
- 输入是片段还是章节
- 输出是新版本还是直接合并
- 是否回写叙事记忆

### 2.3 改写

整理为编辑工具。

需要明确：
- 改写目标
- 结果如何形成版本
- 什么时候成为正式章节

### 2.4 多版本

整理为独立的大功能域。

需要明确：
- 版本怎么生成
- 版本怎么比较
- 版本怎么选择
- 版本怎么合并
- 版本怎么结算为正式章节

## 3. 需要重命名或替换的流程名

- “章节推进” → 建议拆成“章节编辑 / 章节结算 / 章节发布 / 叙事回写”
- 候选稿提交流程 → 逐步替换为正式章节与版本流程
- 草稿流转流程 → 逐步收口为编辑与版本流程

## 4. 需要统一的原则

1. 结果层和过程层分离
2. 事实层和配置层分离
3. 工具层和对象层分离
4. 一切动态变化优先回写叙事记忆
5. 一切静态参考优先归入经纬

## 5. 整理完成的判定

- 正式章节边界清楚
- 叙事记忆边界清楚
- 经纬边界清楚
- 文风提取、改写、扩写、多版本各自定位清楚
- 旧中间概念不再出现在主路径里
