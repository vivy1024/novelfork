# 多版本流程

## 目标

多版本是用户感知强的大功能域，不是候选稿的改名。

它负责让用户比较、选择、合并和结算不同表达方案。

## 推荐流程

```text
用户选择文本或章节
  → 指定版本生成目标
  → 生成多个版本
  → 展示差异和说明
  → 用户选择、合并或继续派生
  → 结算到正式章节
  → 必要时产生叙事记忆事件
```

## 多版本来源

- 同一片段的多个改写版本
- 同一章节的多个表达版本
- 同一情节的多个走向版本
- 不同风格预设下的文本版本

## 用户能力

- 并排查看
- 差异高亮
- 选择一个版本
- 局部合并
- 继续派生
- 回退
- 结算为正式章节

## 设计原则

1. 多版本是体验层功能，不是候选稿状态机
2. 版本本身不是叙事事实
3. 只有被结算并影响故事的结果才进入叙事记忆
4. 多版本必须服务于用户选择，而不是增加对象负担
