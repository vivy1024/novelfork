# 删除清单

## 1. 已明确要删除的概念

### 1.1 候选稿体系

- 候选稿
- 候选稿生命周期
- 候选稿中心化入口
- 候选稿相关状态流转

### 1.2 草稿体系

- 草稿
- 草稿生命周期
- 草稿中心化入口
- 草稿相关状态流转

### 1.3 中间态对象模型

- 候选稿 / 草稿 / 章节三态并行模型
- 章节推进这一类容易扩张成新业务层的中间概念
- 依赖 accept / reject / archive / restore 的旧工作流

### 1.4 双存储主语义

- SQLite 作为章节资源主存储
- 文件系统 + SQLite 双主语义
- 兼容回退被当成长期架构

## 2. 已明确要删除或废弃的入口

### 2.1 以候选稿为核心的入口

- `candidate.create_chapter`
- 以 candidate 语义命名的主入口
- 任何把候选稿当作最终用户对象的 API / UI

### 2.2 依赖旧中间态的入口

- 以 `accept` 为中心的候选稿提交流程
- 以 `reject` 为中心的候选稿驳回流程
- 以 `archive` / `restore` 为中心的旧资源管理流程

### 2.3 绑定旧概念的存储入口

- 为候选稿和草稿单独维护的资源表语义
- 为候选稿和草稿单独维护的文件索引语义
- 对 SQLite 和文件系统同时承担业务主职责的代码

## 3. 删除原则

1. 先删概念，再删入口
2. 先删用户可见层，再删内部兼容层
3. 先删旧命名，再删实现分支
4. 删除前必须确认正式章节、叙事记忆、经纬不受影响

## 4. 删除后应保留的东西

删除候选稿和草稿，并不意味着删除写作能力。

应保留的是：

- 正式章节
- 叙事记忆
- 经纬
- 预设 / 模板 / 节拍
- 编辑工具和版本工具

## 5. 删除完成的判定

当下列条件满足时，才算真正删干净：

- 代码里不再出现候选稿/草稿作为主对象
- 路由里不再暴露候选稿主入口
- 文档里不再把候选稿/草稿作为推荐流程
- 测试里不再以候选稿作为基础模型
- 代码图谱不再把这些概念作为高频主路径
