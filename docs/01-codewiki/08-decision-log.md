# 决策日志

## 1. 不做微服务拆分

### 结论
当前不拆微服务，继续维持模块化单体。

### 原因
- 现阶段问题主要是概念和边界混乱，不是横向扩展能力不足
- 微服务会把概念混乱、存储混乱、工具混乱进一步放大
- 当前更需要的是收口和删除，而不是拆散

### 影响
- 继续以 `core` / `studio` / `novel-plugin` 的模块化单体方式组织代码
- 所有新功能优先在现有模块边界内收敛

## 2. 保留正式章节

### 结论
正式章节保留为独立业务对象。

### 原因
- 它是写作动作的稳定结果
- 它是可展示、可发布、可回溯的最终产物
- 它不应与候选稿 / 草稿中间态混淆

### 影响
- 正式章节需要独立的生成、编辑、结算和回写边界
- 但不再和候选稿 / 草稿体系绑定

## 3. 删除候选稿与草稿主概念

### 结论
候选稿与草稿不再作为主产品概念维护。

### 原因
- 它们是旧流程留下的中间层
- 会增加对象模型复杂度
- 会让存储和工具继续向历史包袱靠拢

### 影响
- 相关入口需要逐步收口或废弃
- 相关测试、文档、UI 需要同步调整

## 4. 文风提取作为工具

### 结论
文风提取保留为工具，不作为对象。

### 原因
- 它的输出是风格建议，不是事实
- 结果应当进入预设 / 模板 / 节拍配置流程
- 用户需要可手动编辑和确认

### 影响
- 文风提取需要和预设编辑联动
- Agent 需要向用户发起是否加入预设的确认

## 5. 动态事实归叙事记忆，静态设定归经纬

### 结论
叙事记忆与经纬分工继续强化，作为两大主边界。

### 原因
- 动态事实不应混入静态设定
- 静态设定不应被动态写作流程频繁改写
- 这两个边界是系统可理解性的基础

### 影响
- 写作工具的最终落点必须清晰
- 任何新能力都要先判断归属
