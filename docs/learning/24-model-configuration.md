# 模型选择与配置

> 选择适合写作的模型，配置供应商和备用方案。

## 支持的供应商类型

| 协议类型 | 说明 | 示例 |
|----------|------|------|
| Anthropic 协议 | Claude 系列原生协议 | Anthropic API、AWS Bedrock |
| OpenAI 协议 | ChatGPT 兼容协议 | OpenAI、DeepSeek、零一万物 |
| 兼容 API | 任何兼容上述协议的服务 | 本地 Ollama、vLLM、自建代理 |

## 推荐写作模型

| 模型 | 优势 | 适用场景 |
|------|------|----------|
| Claude Opus 4 | 写作质量最高，理解力强 | 正式写作、复杂剧情 |
| Claude Sonnet 4 | 平衡质量与速度 | 日常写作、迭代修改 |
| DeepSeek v4-pro | 性价比高，中文表现好 | 大量写作、预算有限 |

## 如何添加与配置供应商

1. 进入 **设置 → AI 供应商**
2. 点击"添加供应商"，选择协议（Anthropic、OpenAI Completions、Responses、Codex Native、Gemini 兼容或 NUG 网关）。
3. 填写服务信息：
   - **NUG 服务地址与自动前缀**：输入服务地址时自动推导有意义的域名作为服务名称与前缀（如 `http://nug.example.com` 自动推导 `nug` 前缀）；
   - **密钥与代理**：配置 API Key 或选择继承代理/自定义代理。
4. **模型列表与操作**：
   - 模型列表采用极其紧凑的**单行表格布局**（模型 ID · 显示名 · context window · 操作图标）；
   - 支持单个与**一键批量“全部隐藏 / 全部显示”**模型；
   - NUG 反代通道支持查看带可用率百分比进度条的通道健康面板。
5. **脏检测与保存**：界面修改后底部弹出 Dirty Bar（“有未保存的更改”），确认无误后点击“保存变更”批量写入 Runtime。

## Model Fallback（自动切备用模型）

当主模型不可用时，系统自动尝试下一个供应商：

- **503 / 529（过载）**：等待 → 重试 → 切备用
- **429（限流）**：按 retry-after 等待 → 重试 → 超时切备用
- **连接超时**：直接切备用
- **404（模型不存在）**：报错，不切换

切换时 UI 短暂显示"已切换到备用模型"，对话不中断。

## Reasoning Effort（推理深度）

控制模型的思考深度：

| 级别 | 效果 | 适用场景 |
|------|------|----------|
| low | 快速回复，少思考 | 简单问答、格式调整 |
| medium | 平衡 | 日常写作 |
| high | 深度思考，慢但质量高 | 复杂剧情、架构设计 |

注意：不是所有模型都支持 reasoning effort，不支持时该设置被忽略。

## Context Window（上下文窗口）

不同模型的窗口大小决定了能放多少对话历史：

| 模型 | 窗口大小 | 实际可用（扣除系统提示后） |
|------|----------|---------------------------|
| Claude Opus 4 | 200K | ~180K |
| Claude Sonnet 4 | 200K | ~180K |
| DeepSeek v4 | 128K | ~115K |
| GPT-4o | 128K | ~115K |

窗口越大，AI 能记住越多对话内容，压缩频率越低。

## 最佳实践

- **写作用大窗口模型（200K+）**：长篇小说上下文多，避免频繁压缩丢失细节
- **配置两个供应商做 fallback**：保证一个挂了另一个顶上，写作不中断
- **日常用 medium effort**：high 虽然质量好但慢 2-3 倍，创作流畅度也重要
- **检查模型支持的功能**：不是所有模型都支持 tool_use，写作核心流程需要工具支持

## 常见坑

- **API Key 错误** → 返回 401，检查是否复制完整、有无多余空格
- **模型名拼错** → 返回 404，用设置页的"刷新模型列表"确认可用模型
- **Base URL 多了斜杠** → 连接失败，URL 末尾不要加 `/`
- **供应商限流** → 频繁 429，降低并发或换供应商

## Agent 查阅提示

- 供应商配置存储在 settings store 的 providers 字段
- Model fallback 逻辑在 llm/provider.ts 的 chatCompletion 中
- Reasoning effort 通过 API 参数 `thinking` 或 `reasoning_effort` 传递
- 模型列表通过 `/api/providers/:id/models` 端点动态获取
