# 伏笔与记忆：章后结算、记忆过期、重新结算

## 这一步解决什么问题

写到几十章，谁受了伤、谁知道了秘密、哪个伏笔还没收，人脑记不住，AI 更记不住。叙事记忆替你记「已经发生的事」，伏笔账本替你记「欠读者的账」。

叙事记忆：正文里已经发生的事，比如谁在哪、受了什么伤、关系怎么变。

章后结算：写完一章后，让模型读这一章，把发生的事记进叙事记忆。

## 结算什么时候发生

叙述者写完章会自动结算。重要的变化会变成待审事项，出现在写作侧栏的「本章提议」和「故事推进 › 章后事实」里。

你自己改了正文，已经记下的内容可能对不上了，这叫记忆过期。打开那一章时，上方会提示「本章正文在结算后已被修改——叙事记忆可能过期，建议重新结算」。

## 在哪里点

活动栏点「故事推进」。侧栏最上面显示当前第几章，下面一行是建议你接着做的事，比如「处理章后待审事件」「重新结算记忆过期的章节」，点它直接过去。再往下有四个标签：「章节与大纲」「章后事实」「故事画布」「进度账本」。

「章后事实」：上面是「记忆过期的章节」，每章一个「重新结算」；下面是「章后事实与故事状态」，显示待审事项和已结算记忆的条数，点「在中央打开章后事实」可以逐条处理。

「进度账本」：伏笔、冲突、资源账都在这里，顶部显示待回收、本章到期、未收束、遗忘各有几条。点「打开看板」看伏笔看板。

## 推荐使用流程

1. 每写完一章，到写作侧栏的「收尾」：先点「结算第 N 章」，再看「本章提议」，对的点「确认」，错的点「驳回」。已经结算过但觉得漏记了，点「强制重新结算（上次漏记时用）」。
2. 积压多了，去「在中央打开章后事实」。可以按置信度筛选，用「批量批准」一次处理，也可以「改后批准」。
3. 自己改过更早的章节后，到「记忆过期的章节」点「重新结算」。它用「设置 › 模型」里的默认模型。
4. 要埋伏笔，对叙述者说「在这章埋个伏笔：某某，第 20 章前收」。它会先给你看方案，再写进经纬。
5. 在「进度账本」里改伏笔状态：已埋设、部分揭示、唤醒中、已触发、已回收、已废弃。

## 结果去哪里

确认过的变化进叙事记忆，写后面的章时会被召回。记忆过期的章节，它的摘要照样会给 AI 看，但会标明「可能过期、以正文为准」。

伏笔只认经纬里的伏笔条目，也就是作品基础的设定库。结算发现新埋的伏笔时，会先写成待确认的草稿，你确认后才开始计算到期。

## 最佳实践

- 伏笔提醒的快慢在「写作设置 › 写作参数 › 伏笔提醒阈值」里调，默认埋下 5 章开始提醒、12 章判为超期。快节奏的书调小，慢热长篇调大。
- 不要把废稿结算进记忆。废稿先让叙述者作废，见「写下一章」。

## 常见问题

- 点「重新结算」报错说没有模型：先在「设置 › 模型」选好默认模型。
- 写作侧栏提示「近章记忆」：有正文但一直没结算过。点「一键修」，让叙述者把历史章节补结算一遍。
- 记忆里有一条是错的：在正文里按住 Ctrl（Mac 上是 ⌘）点人名打开资料卡，在状态上点「纠正」或「作废」。
- 伏笔到期了但这章不想收：推进一点，或改到期章，别让它无声消失。

## Agent 查阅提示

- 伏笔以经纬伏笔条目为准，用 `hooks.manage` 列出、埋设、兑现；部分揭示用 `lore.progress`。
- 补结算历史章节用 `memory.settle_range`；单章用 `memory.settle_chapter`。
